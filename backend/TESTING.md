# 测试记录（TESTING.md）

记录在本目录实际执行的验证，均为离线测试（SQLite + 内存假 Redis），
不依赖 MySQL/Redis 容器。依赖：fastapi、sqlalchemy、pydantic、redis、
httpx、pyjwt、numpy、scipy。

## 1. 算法与持久化 / worker 续算
```
cd backend && PYTHONPATH=. python3 tests/test_cluster_offline.py
```
实测通过 8 组：
1. `best_segment` 对暴力枚举（n≤11 随机串），含「同分起点最早、再取最短」。
2. 精确概率 DP 对全部 C(n,K) 摆法枚举（n≤10，各 K）。
3. 逐件判定归一化与 160 件超容量拒绝（含布尔、非法值、空数组）。
4. SQLite 持久化、版本乐观锁（旧版本 409）、容量 422。
5. 开跑冻结同一版记录；之后更正照常录入且不影响已排队快照。
6. DP 跑到一半模拟中断，再从检查点续算，结果与一次算完完全一致；
   运行中 `result` 始终为空（未算完不出概率）。
7. 160 件满容量端到端：40 连漏块达标摆法 121 个（并列全计入），
   约分分数 1/713891079121949381611543371927954800。
8. 无漏 / 全漏边界概率为 1。

## 2. HTTP 接口端到端
```
cd backend && PYTHONPATH=. python3 tests/test_cluster_api.py
```
实测通过：
- 未登录 401；viewer 写入 403、可读结果。
- 首次登记、版本冲突 409、非法判定与超容量 422（带明确中文原因）。
- 开跑响应不含检查点层；冻结 v2 后更正到 v3，排队计算仍为 v2。
- worker 实算后段序号范围与精确分数字符串正确（[1,1,0,0] → 段 1–2，分数 1/2）。
- 原 Fisher 工艺比较链路不回归（p=0.03978781047861003）。
- 160 件满容量经 HTTP 端到端，达标摆法 121。

## 3. 前端
- 全部 `frontend/src/**/*.js` 通过 `node --check` 语法校验。
- 大整数（C(160,80) 达 47 位）由后端以字符串下发，前端按字符串逐位显示，
  不经过 JS Number，避免丢精度。

## 独立原型对拍
`/tmp` 下独立原型（不引用应用代码）对最优段与精确概率做全枚举交叉验证，
n=160、K=80 全扎堆情形概率为 1/C(160,80)≈8.8e-46，与单摆法事实一致。
